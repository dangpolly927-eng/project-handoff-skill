## Project name

Working title: Cross-border Email Messenger

## Project background

People in different countries often rely on different dominant chat apps. That creates friction when two people need to communicate across markets without both adopting the same platform. Email is globally interoperable, but normal email UX is cumbersome for everyday conversation.

## Original problem to solve

Make cross-border communication easier without depending on both sides using the same social/chat platform.

## Target users

Start with people who need cross-border communication, especially business users.

## Core product idea

Use normal email accounts/infrastructure as the interoperable transport and identity layer, while presenting messages in a modern chat-style interface.

## Ultimate goal

Create a simple cross-provider communication product that feels closer to chat while retaining email interoperability and not requiring the recipient to install the same product.

## Current MVP goal

- User can connect/authorize an email account.
- User can start a conversation using another person's email address.
- Messages appear in a modern chat-thread UI.
- Replies remain synchronized with email.
- Translation can be offered as a convenience.
- MVP does not depend on private WeChat, LINE, or WhatsApp protocols/APIs.

## Non-negotiable principles

- Preserve cross-provider email interoperability.
- Do not require the recipient to install the product for basic communication.
- Keep the experience simple and chat-like.
- Do not let later agents silently turn the MVP into a different product.

## Explicitly out of scope for now

- Depending on private third-party chat protocols.
- Treating translation as the core technical moat.

## Original success condition

A user can connect email, start a chat-style conversation with an ordinary email address, and exchange synchronized replies across email providers without requiring the recipient to install the product.
