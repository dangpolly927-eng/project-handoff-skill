# CURRENT PROJECT ORIGIN — EXAMPLE FROM THE PRESENT PROJECT

Use this only as a starting example when initializing the current cross-border messaging project. Confirm against the actual project conversation and user-approved decisions.

## Project name

Working title: Cross-border Email Messenger

## Original problem to solve

People in different countries often use different dominant chat apps, which creates friction in cross-border communication. Email is globally interoperable, but its normal user experience is slow and cumbersome for everyday conversation.

## Target users

Start with people who need cross-border communication, especially business users. Do not require both sides to adopt the same social app.

## Core product idea

Use normal email accounts / email infrastructure as the interoperable transport and identity layer, but present messages in a modern chat-style interface. A user can communicate across different email providers while the product makes the experience feel closer to instant messaging.

## MVP direction

- User can connect/authorize an email account.
- User can start a conversation using another person's email address.
- Messages appear in a modern chat-thread UI rather than traditional email UI.
- Replies remain synchronized with email so the other side can still use ordinary email.
- Translation can be offered as a simple AI convenience; it is not treated as the main technical moat.
- MVP does not depend on private WeChat, LINE, or WhatsApp protocols/APIs.

## Non-negotiable principles

- Preserve cross-provider email interoperability.
- Do not require the recipient to install the product for basic communication to work.
- Keep the user experience simple and chat-like.
- Do not let later agents silently turn the MVP into a different product.
- Routine technical choices should be handled by the project/development lead and coding harness without repeatedly asking the user.

## Working arrangement

- User: product owner and final decision-maker on major direction.
- Primary AI: project/development lead and continuity owner.
- Coding harness: programmer/implementation executor.

## User-facing communication rule

Keep explanations short, concrete, and in plain Chinese. Avoid jargon and long walls of text.
