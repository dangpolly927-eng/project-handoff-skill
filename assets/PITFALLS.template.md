# PITFALLS

> Append-only project learning. Do not delete older entries.

Record mistakes only when they can realistically prevent repeated wasted work or protect important systems.

## Types

- `confirmed_pitfall`: repeating the same path unchanged is predictably wrong.
- `failed_attempt`: this specific implementation/approach failed; another approach may still succeed.
- `high_risk`: the operation can materially damage data, production, shared infrastructure, accounts, security, or another important system.

## Entry format

### PIT-001 — Short title

- Date/session:
- Type: confirmed_pitfall / failed_attempt / high_risk
- Status: active
- Tried / observed:
- Result:
- Known reason:
- What to do next time:
- What not to repeat unchanged:
- Related step/files/checkpoint:

If later evidence changes the conclusion, keep the old entry and append a status update such as `superseded` or `no_longer_applicable` with the reason.
